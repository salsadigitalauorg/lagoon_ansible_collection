**Date:** 2026-09-08
**Story:** P3-S4 (`docs/plans/v3-phase3-stories.md`), superseded in detail by
[`docs/plans/2026-09-04-p3-s4-project-golden-target.md`](./2026-09-04-p3-s4-project-golden-target.md)

**Audience:** the `code` agent implementing P3-S4

---

## Why this document exists

P3-S4 has repeatedly failed to land. The presenting theory was file size.
Measured, that is a symptom, not the cause.

The real cause is an **ordering deadlock** in the story as written:

- `project.py`'s bounded-hop read cannot pass the sweep until the guard is
  fixed. Reproduced against the real guard: the full read document classifies
  as `undeclared_nesting` on `openshift` when `assert_flat_query` is called
  the way the sweep calls it (no `parent_type`).
- The guard fixes cannot be proven by anything in the tree until a
  bounded-hop read exists to prove them against.

The story mandates both in **one commit**, so there is no green checkpoint
anywhere between "nothing written" and "everything written" — a single
big-bang integration of ~1,500 new lines. That is the failure mode.

Size is real but secondary: `project.py` lands at ~880 lines, of which ~390
are `DOCUMENTATION`/`EXAMPLES`/`RETURN` for 42 options. Handled by writing it
in four sequential passes (§3), not by splitting the file.

### Deviation from the plan document (rule 5)

`2026-09-04-p3-s4-project-golden-target.md` §"P3-S4 (revised)" states the
Finding 1 guard fixes are folded into P3-S4's own commit *"per explicit
instruction"*. **This plan splits them into a preceding commit** (§2),
confirmed with the owner.

Rationale: that instruction is precisely what creates the deadlock, and it
contradicts the precedent the same document sets twice. P3-S3a and P3-S4a
were both split out ahead of P3-S4 with the stated reasoning that *"the
golden target must be built against a settled rule, not one changing
underneath it in the same commit."* A guard that cannot pass a legal read is
not a settled rule. Record this deviation in the commit body.

### Guard defects — both reproduced

1. **`parent_type` is never passed by the sweep.** The full `project` read
   document raises `undeclared_nesting` on `openshift` with no `parent_type`,
   and **passes** with `parent_type='Project'`. Same document, opposite
   verdicts.
2. **A module-level `fields` constant resolves to `UNRESOLVED_BUILD_QUERY`.**
   Reproduced with a fixture using `fields=_FIELDS` carrying a deliberately
   *illegal* `deployTargetConfigs` hop: the sweep records the placeholder and
   `continue`s past it, so the illegal hop is never examined. A genuine
   vacuous pass.

`sdl_object_type_fields` already parses `Query` (62 fields) and `Mutation`
(167 fields) correctly, so the fix has the data it needs:
`Query.projectByName -> Project`, `Mutation.deleteProject -> String`.

### Every document this story builds — verified to pass

With `parent_type` resolution in place, all four pass the real guard:

```
query projectByName($name: String!) { projectByName(name: $name) { <33 scalars>
  openshift { id } kubernetes { id }
  autogeneratedRouteConfig { enabled allowPullRequests prefixes

mutation updateProject($input: UpdateProjectInput!) { updateProject(input: $input) { id } }
mutation deleteProject($input: DeleteProjectInput!) { deleteProject(input: $input) }
```

The read is depth 4 and legal under P3-D18; `privateKey` is absent from it
(P3-D17). 33 scalar leaves = 34 plain scalars on `Project` minus `privateKey`.

### Description coverage — confirms Finding 4

Step 1 (input SDL description): **0/42.** Step 2 (`Project`, plus
`AutogeneratedRouteConfig` for the ARC-backed names): **29/42.** Step 3
(manual text required): **13** — the five `activeSystems*`,

Finding 4's prose says "12 truly at step 3", reasoning that

### Option-name mapping — no collisions, four to watch

`resource.py::_camel_to_snake` drives the wire↔argspec mapping. All 42 names
map without collision. Four would silently **drop the option** if the
argspec spells them differently, because `_desired_from_params` skips any
field whose derived key is absent from `params`:

| Wire | Argspec key must be exactly |
| --- | --- |
| `problemsUi` | `problems_ui` |
| `factsUi` | `facts_ui` |
| `addOrgOwner` | `add_org_owner` |
| `sharedBaasBucket` | `shared_baas_bucket` |

A test must assert every one of the 42 derived keys is present in the
argspec (§4, test 15) — this is a whole class of silent-drop bug.

## 2. Commit 1 — guard fixes

Both fixes live in `tests/unit/plugins/module_utils/query_depth.py`. No
`plugins/` file changes. No `graphql-core`; SDL parsing stays regex-based.

### 2a. Resolve `parent_type` from the document's root field

Add a helper that, given a document and the SDL text, extracts the root
field name and resolves its return type via the existing
`sdl_object_type_fields(sdl_text, 'Query')` then `..., 'Mutation')`,
stripping `[]!` to a bare type name.

Wire it into the sweep's call site in
`test_query_depth.py::TestSweep::test_sweep_runs_clean_against_current_plugins_tree`,
so `assert_flat_query(document, source=source, parent_type=<resolved>)`.

Falls back to `None` (today's behaviour) only when the root field resolves to
neither root type. **Never** silently narrow coverage for a document that
*can* be resolved.

Design note for the reviewer: the resolution helper belongs in
`query_depth.py` (it is guard machinery, reusable by any caller), while the
sweep's own call site is in `test_query_depth.py`. Keep that split.

### 2b. Resolve a module-level constant passed as `fields`

`_literal_from_ast` raises on an `ast.Name`, so `fields=_PROJECT_READ_FIELDS`
becomes `UNRESOLVED_BUILD_QUERY` and is skipped unchecked.

Extend the resolution path so a bare `ast.Name` referring to a
**module-level constant already collected from the same tree** resolves to
its literal value. Two constraints:

- `_module_and_class_level_assigns` currently collects **string constants
  only** (`isinstance(value.value, str)`). A `fields` list is an `ast.List`.
  Either widen it or add a sibling collector — do not break its existing
  callers, which expect string documents.
- Anything not a plain module-level name (a computed expression, a call, a
  comprehension) must still resolve to `UNRESOLVED_BUILD_QUERY`. "Not
  checked" stays honest; only the statically-knowable case improves.

### Tests — each fix must fail independently when reverted

This is the acceptance bar the plan document sets, and it is the one most
likely to be met only superficially. Two synthetic fixtures, no dependency on
`project.py` (which does not exist yet at this commit):

1. **`parent_type` fix:** a fixture with a legal, *declared* bounded hop
   written as an **inline literal** (`fields=['id', {'openshift': ['id']}]`).
   Fails with the old no-`parent_type` sweep, passes with the fix. Its
   discriminating pair: the same fixture with an **undeclared** hop
   (`deployTargetConfigs`) must still fail.
2. **Constant-resolution fix:** a fixture with an **illegal undeclared** hop
   reached via a module-level `_FIELDS` constant. Before the fix the sweep
   records `UNRESOLVED_BUILD_QUERY` and skips it; after, it is a real
   violation. Assert on the *reason* (`undeclared_nesting`), not merely that
   something raised.

Fixture 1 uses an inline literal and fixture 2 a module-level constant
deliberately, so reverting either fix alone leaves exactly one test failing.
State that in a comment on each test — a future partial revert is otherwise
easy to miss.

Also re-assert, unchanged: `V1_PROJECT_INFO_QUERY` still fails, and P3-S3a's
`environments { id }` / `environments { openshift { id } }` discriminating
pair still gives opposite verdicts.

### Commit 1 message

```
fix(v3): resolve parent type and constant fields in the query sweep

The sweep called assert_flat_query with no parent_type, so the registry
lookup fell through to an empty dict and every nested selection
classified as undeclared_nesting -- including one legally declared in
PERMITTED_NESTED_SELECTIONS. A bounded-hop read could not pass the
guard at all, regardless of the registry.

Separately, a fields list held in a module-level constant resolved to
UNRESOLVED_BUILD_QUERY, which the sweep skips rather than checks. That
is a vacuous pass in its own right: a nested-and-wrong read written
that way was never examined. Reproduced with a fixture carrying an
undeclared hop behind a constant.

Both are guard-correctness fixes applying to every future bounded-hop
read. Split out ahead of the project module rather than folded into
its commit, so the golden target is built against a guard that can
already pass a legal read -- the same reasoning that put the
selection-shape rule and its bounded-list extension in their own
commits.

Refs docs/plans/2026-09-04-p3-s4-project-golden-target.md Finding 1
```

## 3. Commit 2 — `plugins/modules/project.py` in four passes

Single file (standard Ansible module layout, and what P3-S9's generator must
emit byte-for-byte). Written in four passes, verifying after each, so no
single write approaches 880 lines.

Structural shape follows `whoami_info.py`: fully-qualified absolute imports,
`run_module(module)` taking a params-bearing object, `main()` wiring
`AnsibleModule` + `auth.auth_argument_spec()`.

### Pass 1 — skeleton, constants, `main()`

Module-level tables, each a plain literal so commit 1's constant resolution
can see them:

- `_FIELDS` — the 42 wire names (diffable set for `resource.py`).
- `_READ_SELECTION` — the 33 scalars + 3 hop mappings, exactly as verified
  in §0. `privateKey` excluded (P3-D17).
- `_CREATE_ONLY` — `('organization', 'addOrgOwner')`. `id` is not in this
  tuple (see the correction in §0 above) — it is the update key, held in
  `_DIFF_IGNORE`, never a caller-supplied option.
- `_UPDATE_ONLY` — the 6 names.
- `_CREATE_REQUIRED` — `('gitUrl', 'productionEnvironment')` (P3-D15;
  `name` is argspec-required so it is not repeated here).
- `_NO_LOG_FIELDS` — `('privateKey',)`.
- `_UNREADABLE_CREATE_ONLY` — `('addOrgOwner',)`.

Gate: `python -c "import ast; ast.parse(open('plugins/modules/project.py').read())"`.

### Pass 2 — the four closures and enforcement

- **read** — `build_query('projectByName', fields=_READ_SELECTION,
  args={'name': 'String!'})`; returns `None` when `projectByName` is null.
  Flattens each hop into the wire-field namespace: `openshift {id}` →
  `openshift`, `kubernetes {id}` → `kubernetes`, and ARC's four scalars →
  their **input** names (`enabled` → `autogeneratedRoutes`,
  `allowPullRequests` → `autogeneratedRoutesPullrequests`, `prefixes` →
  `autogeneratedRoutePrefixes`, `disableRequestVerification` →
  `disableRequestVerification`), `pathRoutes` → `autogeneratedPathRoutes` as
  a list of dicts keyed like the argspec's `options`.

  Drive the flattening from a small declarative table, not inline `if`s —
  P3-S9's generator must reproduce this from allowlist data, so a hard-coded
  sequence of hop-specific statements would not generalise. This is the
  review focus item "is anything here a shortcut that would not generalise".

- **create** — enforce `_CREATE_REQUIRED` first, raising `LagoonConfigError`
  naming every missing option, **before** any mutation call. Then
  `addProject(input: {...})`, flat, `create_only` permitted.

- **update** — `updateProject(input: {id: <id>, patch: {...}})`. The nested
  shape is the single most regression-prone line in the story; assert on the
  exact `variables` dict.

- **delete** — `deleteProject(input: {project: <name>})`, `fields=[]`,
  matching `DeleteProjectInput { project: String! }` (SDL:2407-2409, verified
  — **not** `id`).

- **create-only enforcement (P3-D16)**, applied when `current is not None`,
  keyed only on readability:
  - in `_FIELDS` and equal to current → no-op for that field;
  - in `_FIELDS` and different → `LagoonConfigError` naming both values, and
    for `organization` naming `removeProjectFromOrganization` /
    `bulkImportProjectsAndGroupsToOrganization` as the supported path.
    Never call either;
  - not readable (`addOrgOwner`) → `LagoonConfigError` unconditionally.

  `id` is not in `_CREATE_ONLY` — it is only in `diff_ignore`, is never a
  caller-supplied option at all (no argspec entry), and this enforcement
  never sees it. Enforcement still must key on *supplied* params rather
  than on table membership, for `organization`/`add_org_owner`.

- **`private_key` (P3-D17)** — never read; reported only via
  `changed_no_log_fields`; sent by create/update whenever supplied.

Gate: `docker compose run --rm test-v3 units -v --requirements
tests/unit/plugins/module_utils/test_query_depth.py` — the sweep now sees
`project.py`'s real documents and must pass clean.

### Pass 3 — the 42-option argspec

Only `name` is `required=True` (P3-D15). `no_log=True` on `private_key`
only. `choices` for `availability` (`STANDARD`, `HIGH`, `POLYSITE` — three,
per SDL:93-97) and `restrictions` (`type='list'`, `elements='str'`, five
choices). `autogenerated_path_routes` is `type='list'`,
`elements='dict'`, `options=` with `from_service`/`to_service`/`path`.
`autogenerated_route_prefixes` is `type='list'`, `elements='str'`.

`activeSystems*` and `deploymentsDisabled` are `@deprecated` in the SDL but
remain in the input types — keep them, and say so in their descriptions.

Gate: full unit suite green, including the derived-key test (§4, test 15).

### Pass 4 — `DOCUMENTATION`, `EXAMPLES`, `RETURN`

~390 lines. 29 descriptions adapted from the SDL, 13 hand-written (§0).
Options needing explicit prose beyond a description:

- create-only three: state the behaviour against an existing project.
- `private_key`: write-only — drift cannot be detected.
- update-only six: only applied on update.
- `add_org_owner`: no effect on `state: present` against an existing project.

**No `no_log:` key in `DOCUMENTATION`** — `antsibull-docs`' `OptionsSchema`
sets `extra="forbid"` and fails the lint. Redaction is argspec-only.

Gate: `docker compose run --rm lint-docs-v3`.
